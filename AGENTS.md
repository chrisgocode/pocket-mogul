# Pocket Fortune

Portrait mobile idle wealth game (React Native + Expo + TypeScript). Planning lives in the wayfinder map: https://github.com/chrisgocode/pocket-mogul/issues/1

## Agent skills

### Issue tracker

Issues are tracked in GitHub Issues for `chrisgocode/pocket-mogul` via the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Domain docs

Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Git workflow

`main` is protected: no direct pushes, force-pushes or deletion. Every change goes through a pull request, which merges only when the CI `Check` job passes. Work on a branch and open a PR.

## Build plan

The v1 build follows `docs/spec.md` §19 in six phases. Each phase is a sub-issue of https://github.com/chrisgocode/pocket-mogul/issues/19 (Phase 1 is #38). Refer to work by its issue number.

## Expo

Expo SDK 58. Expo changes between SDKs, so check the versioned docs at `https://docs.expo.dev/versions/v58.0.0/` (index: https://docs.expo.dev/llms.txt) before touching an Expo or React Native API.

- No comments in code: lint rejects every comment (`lint-rules/pocket-mogul.mjs`). If code needs one, rename or restructure it until it explains itself. Context that belongs outside the code goes in the spec, README or an ADR.
- Save format (`src/application/saveSchemas.ts`, `docs/spec.md` §14): add a field without bumping `SAVE_SCHEMA_VERSION`. Declare it at the top level of the save with a neutral default (empty list, `none`, "not started") and test that `src/application/fixtures/save-baseline.json` loads with it. Never default money or progress (cash, quantities, cost basis, time). Bump the version, add an upgrade step to `SAVE_FORMAT.migrations` and a fixture only for a breaking change (rename, removal, type or unit change, new meaning), and raise the minimum reader version when an older build would misread the result.
- Content (`src/content/economy-v1.ts`) is the versioned economy from `docs/spec.md`. Retune it by bumping `economyVersion`, never reuse an ID (list retired ones in `retiredIds`), and keep names fictional: they nod at a sector, never a real brand.
- Bun is the package manager (`bun.lock`). Use `bun install`, `bun run <script>` and `bunx`, never npm or npx.
- Add packages with `bunx expo install <package>` so versions match the SDK.
- Development builds only, never Expo Go. `ios/` and `android/` are generated by prebuild: configure native behavior in `app.json` and config plugins, never by hand.
- Routes live in `src/app` (Expo Router); keep non-route code outside it.
- Run `bun run check` (typecheck, oxlint, oxfmt check, tests) before declaring work done. Run `bun run format` to format.
- Tests: logic and engine tests are `*.test.ts` under `src/domain`, `src/content` or `src/application`, use the global `describe`/`it`/`expect` (don't import them from `bun:test`, or oxlint's Jest rules can't see them), and run with `bun run test:logic`. Screen tests are `*.test.tsx` and run on Jest with jest-expo (`bun run test:screens`), because `bun test` can't load React Native. Use the scripts, not bare `bun test`.
- React Native Testing Library 14 is async: `await` `render`, `renderRouter` and `fireEvent`. oxlint enforces this.
- Quality gates (lint, `.oxlintrc.json`; each is proven by `lint-rules/rules.test.ts`):
  - No `useEffect`/`useLayoutEffect` outside named hooks in `src/ui/effects`, and no `useState`/`useReducer` outside named hooks in `src/ui/state`. Game values come from the engine snapshot.
  - Functions at most 40 lines (80 in tests), files 300, complexity 8, cognitive complexity 10, nesting depth 3, 3 parameters (pass an object instead), one component per file.
  - Module boundaries from spec §13: `src/domain` imports no React, Expo or outer layers; `src/content` imports only `src/domain`; `src/ui` can't import features, routes, the engine or adapters; screens never import `src/infrastructure`. Cross-folder imports use `@/`, never `../`.
  - `tsconfig.json` sets `lib` to ES2022 because the app runs on Hermes, which lacks some newer built-ins (`Array.prototype.toSorted` broke saves on device). Don't raise it, even for tests: rewrite the code instead.
- No `Date.now`, `new Date()`, `Math.random` or timers in `src/domain`, `src/content` or tests: use the injected clock and seeded randomness.
  - No magic numbers outside content, tokens, SVG art and tests: name them.
  - No implicit state machines (`pocket-mogul/no-implicit-state-machine`): no closure with two or more `let`s that inner functions reassign, no type with two or more `boolean` fields, and no hook with two or more boolean `useState`s. Hold one value typed as a discriminated union instead.
  - Tests: no conditionals, snapshots, focused or skipped tests.
  - knip rejects unused files, exports and dependencies.
- Lint is strict and type-aware (`.oxlintrc.json`): no raw text outside `<AppText>`, no inline styles or color literals (use `src/ui/tokens.ts`), no unhandled promises, no `any`, explicit checks instead of truthy strings in JSX conditions. Branded money types may only be cast in `src/domain/money.ts` and `src/content/schema.ts`. Fix the code rather than disabling a rule.
- A pre-commit hook runs lint-staged, the typecheck and all tests. Don't bypass it with `--no-verify`. CI (`.github/workflows/ci.yml`) runs the same checks, and its `Check` job is the required status. When adding a CI job, add it to `Check`'s `needs`.
